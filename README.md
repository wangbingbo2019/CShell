# CShell

CShell identifies control-property genes around a disease core in a directed
gene-regulatory network.  The pipeline reports five classes:

| Label | Meaning | Legacy name |
| --- | --- | --- |
| CP-IND | indispensable/minimal-driver related genes | ISR_CS |
| CP-EXT | extraordinary/control-signature genes | ESR_CS |
| CP-DRV | control-subspace genes | DCS_CS / CLS_CS |
| CP-SEN | control-observability genes | SOS_CS / OLS_CS |
| CP-EFF | control-energy reduction genes | IER_CS / MER_CS |

## Installation

Use the locked conda environment when possible:

```bash
conda env create -f environment.yml
conda activate cshell201910
```

The environment follows the original notebook runtime:

```text
python 3.7.4
numpy 1.17.2
pandas 0.25.1
networkx 2.3
sympy 1.4
```

`requirements.txt` is provided for pip-based installation, but Python 3.7
should be created first.

## Inputs

`scripts/run_pipeline.py` requires these files:

| Argument | Description | Source |
| --- | --- | --- |
| `--network` | two-column directed edgelist, one `source target` edge per line | shipped under `data/network/Directed_network.txt`; replace if you change the network |
| `--disease-core` | disease core genes, one gene per line | user-supplied (the asthma example is shipped under `data/asthma/`) |
| `--indispensable` | global indispensable node list | **pre-computed and shipped** under `data/network/Indispensable.txt` — use it directly |
| `--extraordinary` | global extraordinary node list | **pre-computed and shipped** under `data/network/Extraordinary.txt` — use it directly |
| `--regulation-cc` | `*.ControlCentrality` output for the regulation subgraph | **must be generated by the third-party CalControlCentrality tool** (see [Workflow → Stage 2](#workflow)) |
| `--observation-cc` | `*.ControlCentrality` output for the observation subgraph | **must be generated by the third-party CalControlCentrality tool** (see [Workflow → Stage 2](#workflow)) |
| `--out-dir` | directory for pipeline outputs | created automatically |

### Which inputs are pre-computed vs. user-generated

* **`Indispensable.txt` / `Extraordinary.txt`** — these are network-level files
  that depend only on `Directed_network.txt`.  They are **already provided**
  under `data/network/` for the default network bundled with this repository,
  so you can use them as-is and **do not need to run any third-party tool to
  reproduce the asthma example**.

  Re-generate them only if you switch to a different network.  In that case
  you must first run the third-party **ControllabilityAnalysis** tool on your
  new edgelist to obtain `*.nodetype` / `*.linktype`, then derive
  `Indispensable.txt` and `Extraordinary.txt` from those files (see
  [`docs/pipeline_overview.md`](docs/pipeline_overview.md), Steps 1-2, and
  [`THIRD_PARTY.md`](THIRD_PARTY.md)).

* **`*.ControlCentrality` (regulation & observation)** — these are
  *disease-specific* and depend on the disease core, so they are **never
  shipped pre-computed**.  You must produce them yourself for every new
  disease core by running the third-party **CalControlCentrality v1.1** tool
  on the two subgraphs that CShell Step 4 emits.  See the
  [Workflow](#workflow) section below for the exact procedure.

## Workflow

A complete CShell run for a **new disease core** has three stages.  The
middle stage uses the third-party C++ tool **CalControlCentrality v1.1** and
must be performed by you outside this repository.

```
Stage 1 (this repo)        Stage 2 (third-party tool)       Stage 3 (this repo)
-------------------        --------------------------       -------------------
run_step.py step4    -->   CalControlCentrality        -->  run_pipeline.py
generates                  generates                        consumes everything
regulation_subgraph.txt    regulation_subgraph.txt          and emits the five
observation_subgraph.txt   .ControlCentrality              CP-* gene lists
                           observation_subgraph.txt
                           .ControlCentrality
```

### Stage 1 — build the regulation / observation subgraphs

Run only Step 4 of CShell to produce the two subgraph edgelists that the
third-party tool needs as input:

```bash
python scripts/run_step.py step4 \
    --network      data/network/Directed_network.txt \
    --disease-core data/asthma/disease_core.txt \
    --out-dir      results/asthma
```

After this stage `results/asthma/` contains:

```text
regulation_subgraph.txt
observation_subgraph.txt
```

### Stage 2 — run CalControlCentrality (Step 5, third-party)

CShell does **not** implement Step 5.  You must obtain
**CalControlCentrality v1.1** by Yang-Yu Liu (PLoS ONE 2012) yourself, build
it (it requires GLPK), and run it on each subgraph from Stage 1:

```bash
# Run from the directory containing the CalControlCentrality binary;
# the tool writes its output into ./data/ next to the input file.
./CalControlCentrality . results/asthma/regulation_subgraph.txt
./CalControlCentrality . results/asthma/observation_subgraph.txt
```

This produces the two files CShell needs to continue:

```text
results/asthma/regulation_subgraph.txt.ControlCentrality
results/asthma/observation_subgraph.txt.ControlCentrality
```

How to obtain the package, license terms, and the exact command line are
documented in [`THIRD_PARTY.md`](THIRD_PARTY.md).  Because of the upstream
license we cannot redistribute the binary or the source.

> If you only changed the **disease core** (not the network), Stages 1 and 2
> are the only steps you need to redo.  The network-level files
> `Indispensable.txt` and `Extraordinary.txt` shipped under `data/network/`
> remain valid.

### Stage 3 — run the full CShell pipeline

Once the two `*.ControlCentrality` files exist, run the orchestrator:

```bash
python scripts/run_pipeline.py \
    --network         data/network/Directed_network.txt \
    --disease-core    data/asthma/disease_core.txt \
    --indispensable   data/network/Indispensable.txt \
    --extraordinary   data/network/Extraordinary.txt \
    --regulation-cc   results/asthma/regulation_subgraph.txt.ControlCentrality \
    --observation-cc  results/asthma/observation_subgraph.txt.ControlCentrality \
    --out-dir         results/asthma \
    --seed            0
```

Notes:

* `--indispensable` and `--extraordinary` point at the **pre-computed files
  shipped with the repo**.  Do not regenerate them unless you have switched
  to a different network (see the [Inputs](#inputs) section).
* `--regulation-cc` / `--observation-cc` must point at the **Stage 2 outputs
  for your specific disease core**; they are not shipped.
* Outputs from Step 3 and Step 8 use random sampling; pass `--seed` for
  reproducibility.

## Outputs

The output directory contains:

```text
cshell_genes.tsv       gene-to-control-property table
CP-IND.txt             CP-IND genes
CP-EXT.txt             CP-EXT genes
CP-DRV.txt             union of CP-DRV_part1 and CP-DRV_part2
CP-DRV_part1.txt       top control-subspace genes
CP-DRV_part2.txt       rank-expansion control-subspace genes
CP-SEN.txt             control-observability genes
CP-EFF.txt             control-energy genes
regulation_subgraph.txt
observation_subgraph.txt
```

`cshell_genes.tsv` has two columns:

```text
gene    cp_class
```

A gene selected by more than one control property appears on multiple rows.

## Third-Party Tools

CShell uses outputs from two third-party C++ tools by Yang-Yu Liu.  They are
not redistributed here because they have separate license terms.

1. **ControllabilityAnalysis v1.0**
   Produces network-level controllability files such as `*.nodetype` and
   `*.linktype`.  These files are used to derive `Indispensable.txt` and
   `Extraordinary.txt`.

   Citation:
   Liu Y-Y, Slotine J-J, Barabasi A-L. Controllability of complex networks.
   Nature 473, 167-173 (2011).

2. **CalControlCentrality v1.1**
   Produces `*.ControlCentrality` files for the regulation and observation
   subgraphs.

   Citation:
   Liu Y-Y, Slotine J-J, Barabasi A-L. Control Centrality and Hierarchical
   Structure in Complex Networks. PLoS ONE 7(9): e44459 (2012).

See `THIRD_PARTY.md` for the expected data flow and citation details.
